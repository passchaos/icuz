# Sixteen-unit BMP packing and wide ASCII windows, 2026-11-27

Native UTF-16→UTF-8 conversion now packs sixteen non-surrogate BMP units per
iteration in the mixed kernel, and the ASCII prefix copier checks two
independent thirty-two-unit halves per sixty-four-unit window. The wide BMP
path is entered only after the already-loaded eight-unit window is
surrogate-free, so surrogate-dense text keeps the previous eight-unit and
pair paths. The complete profile compares `6cc9f7f` and `8faa08a` controls,
simdutf 9.5.0, and ICU 78.3.

Mixed-script UTF-16→UTF-8 reuse falls from 1114.120 to 954.880 ns/op
(1.17x) and is 1.08x faster than simdutf's 1029.220 ns/op. Sparse 64 KiB
reuse falls from 8895.690 to 6822.140 ns/op (1.30x) and dense-to-sparse
64 KiB from 20169.090 to 6919.900 ns/op (2.91x); both come from the
preceding phase-switch work plus the wide ASCII window. Surrogate-heavy
64 KiB reuse falls from 24658.900 to 22218.290 ns/op (1.11x). Current reuse
rows exceed the fastest external library in 27 of 30 corpora; the three
remaining rows are listed below and the industry-best goal stays active.

## Method and provenance

- Intel Core i9-13900K, logical CPU 2, Linux x86-64; Zig 0.16.0 ReleaseFast
  native. The unchanged external harness uses GCC 13 `-O3 -std=c++17`,
  simdutf 9.5.0 `haswell`, and ICU 78.3. simdutf source commit:
  `9064366fa571fac03bcd28db35af597e97fba842`.
- All 30 fixed-seed corpora are identical to the
  [phase-switch profile](utf-phase-switching-2026-11-26.md); input hashes
  and exact byte/unit counts are recorded in the raw profile.
- Five rounds and five trials per row, at least 2,000 calls and an 8 MiB
  target per trial. Tables report the minimum across rounds. Each corpus
  runs sequentially in current/external/baseline/reference order, reversed
  in alternate rounds. Compilation and tests finish before sampling.
- Owned APIs validate, size, allocate exactly, convert, and free. Reuse APIs
  perform strict conversion into warmed caller buffers; only reuse rows are
  compared with the external caller-buffer APIs.
- The benchmark executable is built with `strip = true` for both the harness
  and the `utf16` module, matching the external release controls.
  Debug-info codegen changed hot-loop layout enough to move one
  surrogate-heavy reuse row between 21.8 and 35.0 µs/op on the same source;
  stripping removes that variance and is recorded in the
  [raw profile](utf-bmp-16unit-2026-11-27.json). The library itself and the
  test build are unchanged.
- Preserved controls were rebuilt from the named revisions with identical
  stripped flags: `baseline` is `6cc9f7f`, `reference` is `8faa08a`.
  Native binaries check every result against independent std conversion;
  the external harness checks status, length, and contents. The driver
  validates every required row and byte/unit count.
- [Raw profile](utf-bmp-16unit-2026-11-27.json) records every sample, all
  input hashes, binary hashes, and current-source hashes.
- The profile was re-run at `e306bfd` after the UTF-16 validator change:
  every reuse row stayed within 1% of the recorded value except the
  128-byte emoji tail (19.41 vs 18.78 ns, treated as noise), and the three
  sparse gaps were unchanged at 1.053-1.065x. The validator rewrite does
  not move the conversion kernels.

## Implementation and bounds

`bmp_pack.encode16` builds each unit's two lead/continuation words with
sixteen-bit lane arithmetic, interleaves them into four-byte groups, and
emits four table-selected `vpshufb` lanes. The shuffle table stores one
sixteen-byte mask and one byte count per four-unit pattern, for 8 KiB total.
The kernel runs out of line so the mixed-run loop stays compact.

`mixedRun` first loads the existing eight-unit window and computes its
surrogate mask. Only a surrogate-free window probes the next sixteen units;
a clean probe encodes all sixteen, otherwise the previous eight-unit path
runs unchanged. The probe is skipped when fewer than sixteen units remain or
when the output has less than 64 bytes of store room, so exact owned outputs
finish on the bounded eight/four-unit and scalar paths.

The ASCII prefix copier checks two thirty-two-unit halves per iteration and
stores each half as soon as it is proven ASCII. A mixed first half returns
before storing; a mixed second half stores the clean first half and then
hands the second window to the BMP packer. The tail falls back to the
existing thirty-two/sixteen/eight/four-unit cascade.

All loads and stores remain inside the supplied slices. A sixteen-unit lane
stores one full vector per chunk and advances by the exact byte count, with
the last store starting at most 36 bytes past the window start. Padding is
replaced by the next chunk or remains beyond the returned length. Checked
conversion still validates every surrogate pair; the wide path never sees a
surrogate.

## Remaining measured gaps

These rows have a higher minimum reuse latency than the fastest external
control. Small differences within this profile do not establish a durable
ranking.

| Corpus | Direction | Current ns | Fastest external ns | Current/external |
|---|---|---:|---:|---:|
| mixed-dense-to-sparse-4096 | utf16-to-utf8 | 461.440 | 441.560 | 1.045x |
| mixed-dense-to-sparse-65536 | utf16-to-utf8 | 6919.900 | 6527.920 | 1.060x |
| mixed-sparse-65536 | utf16-to-utf8 | 6822.140 | 6500.220 | 1.050x |

The three gaps share the sparse burst structure: long ASCII runs separated by
two-to-eight mixed-width scalars. Table-batched bursts, a uniform sixteen-unit
loop, sixty-four-lane reduces, one-hundred-twenty-eight-unit windows,
`vptest`-based checks, a sparse-only scalar writer that drops the
redundant ASCII test, and a wide eight-unit burst packer with mixed-run
prefix/pair handling were all measured and rejected. The eight-unit packer
was 11-17% slower on the sparse rows even though it consumed the same
burst windows. The wide two-half
ASCII window is the only variant that improved these rows; the scalar
writer's apparent gain did not survive the full interleaved profile.
Further progress needs a different burst/ASCII split.

## Reproduce

```sh
zig build bench-utf16-build
python3 bench/utf16/compare.py \
  --icuz zig-out/bin/icuz-utf16-bench \
  --baseline /tmp/icuz-utf16-6cc9f7f-strip --baseline-reuse \
  --reference /tmp/icuz-utf16-8faa08a-strip \
  --external /tmp/icuz-transcode-external \
  --cpu 2 --rounds 5 --interleave-cases \
  --output /tmp/icuz-bmp16.json
zig build-exe -O ReleaseFast -fstrip -lc --dep utf16 \
  -Mroot=bench/utf16/profile/to_utf8.zig \
  -O ReleaseFast -Mutf16=src/unicode/utf16.zig \
  -femit-bin=/tmp/icuz-utf16-checked
perf stat -x, \
  -e cpu_core/cycles/u,cpu_core/instructions/u,cpu_core/branches/u,cpu_core/branch-misses/u \
  -- taskset -c 2 /tmp/icuz-utf16-checked /tmp/mixed-4096.bin 30000
```

Preserved controls are rebuilt from the named revisions with the same Zig
version and the stripped release flags. Generate the input files with
`bench/utf16/corpus.py`; the
[phase-switch profile](utf-phase-switching-2026-11-26.md#reproduce) shows
the file-writing procedure.

## Validation

- Native ReleaseSafe UTF module: 63/63 passed.
- Full library Debug test step: 538 passed, two environment-gated skips
  (540 total).
- Debug guarded buffers cover every partial ASCII stop through 257 units,
  dense/sparse transitions, long ASCII prefixes followed by Latin, Chinese,
  supplementary, and mixed text, and exact owned outputs.
- Phase oracles check exact owned allocations, exact/spare caller capacities,
  native endianness, malformed surrogate/UTF-8 neighbors, preserved prefixes,
  and invalid-input precedence.
- AArch64 and big-endian PowerPC64 ReleaseSafe compile-only checks passed.
- Formatting and patch whitespace were checked before sampling.
