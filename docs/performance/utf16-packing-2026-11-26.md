# UTF-16 packing and direct surrogate encoding, 2026-11-26

Strict native-endian UTF-16 conversion now uses smaller BMP packing tables,
one shared bounds check for paired lane stores, and direct surrogate-to-byte
arithmetic. The complete profile compares the immediately preceding `854fca0`
and earlier `1af201c` implementations, simdutf 9.5.0, and ICU 78.3.

The large Latin UTF-16→UTF-8 reuse row falls from 520.058 to
467.387 ns/op (1.11x); large mixed input falls from
1124.932 to 1108.609 ns/op (1.01x). Pure emoji
falls from 407.412 to 397.901 ns/op. Large mixed conversion still
takes 7.5% longer than simdutf's 1030.824 ns/op.
These samples exceed both external libraries in 33/34 reuse rows;
this selected corpus and hardware profile do not establish the broader
industry-best objective.

## Method and provenance

- Intel Core i9-13900K, logical CPU 2, Linux x86-64; Zig 0.16.0 ReleaseFast
  native. The unchanged external harness uses GCC 13 `-O3 -std=c++17`,
  simdutf 9.5.0 `haswell`, and ICU 78.3.
- Seventeen identical files cover ASCII, accented Latin, Chinese, mixed
  scripts and emoji, pure emoji, and short tails around 31 bytes. Names use
  minimum UTF-8 sizes; exact byte counts and native UTF-16 unit counts are
  recorded in the JSON.
- Five rounds and five trials per row, about 8 MiB of original corpus bytes
  per trial and at least 2,000 calls. Tables report the minimum ns/op across
  all rounds. Raw samples retain workstation load and short-row variation.
- For each corpus, libraries run sequentially on CPU 2 in
  icuz/external/854fca0/1af201c order, reversed in alternate rounds. This
  task's compilation and tests finish before sampling.
- Owned rows validate, size, allocate exact output, convert, and free it.
  Reuse rows perform strict conversion into warmed caller buffers. Only
  reuse rows are compared with simdutf and ICU caller-buffer APIs.
- Native binaries check output against independent std conversion. The
  external harness checks status, output length, and contents. The driver
  checks every required row, input length, and output size.
- Preserved predecessor and external binary hashes were checked against the
  [mixed-window profile](utf16-mixed-windows-2026-11-26.json) before use. Its
  current binary is `854fca0`, and its baseline is `1af201c`. simdutf source
  commit: `9064366fa571fac03bcd28db35af597e97fba842`.
- [Raw profile](utf16-packing-2026-11-26.json) records every sample and all
  input, binary, and current-source hashes. `baseline` means `854fca0`;
  `reference` means `1af201c`. Final source and executable hashes were audited
  after validation and sampling.

## Implementation and coverage

The 256 BMP shuffle masks and byte counts are stored in separate arrays.
Their logical size falls from 8 KiB of padded records to 4.25 KiB, and loading
a count no longer depends on the larger record stride. Four- and eight-unit
packing share the established u32 byte arithmetic.

The two output lanes share a fast capacity check for both padded 16-byte
stores. Exact outputs near the end of the slice keep the bounded stores.
The shortcut never writes before the supplied output start or beyond its
capacity. Latin packing also reuses this lane-store helper.

The scalar, two-pair, and eight-pair surrogate encoders share direct u16
arithmetic for the two halves of each four-byte UTF-8 scalar. They no longer
assemble a full code point before extracting its UTF-8 bytes. Isolated pairs
also bypass the generic scalar encoder.
The SIMD output keeps its big-endian byte swap, while scalar words use an
explicit little-endian write to emit UTF-8 byte order on every target.

A new independent std oracle exhausts every supplementary scalar
(`0x10000..0x10ffff`) through scalar writes and checked/prevalidated two-pair
and eight-pair SIMD blocks, with exact output slices and preserved prefixes.
Existing tests cover every BMP width pattern, all 65,536 mixed eight-scalar
width tuples, malformed neighbors, allocation failure, and guarded inputs.

Diagnostic variants with narrower BMP arithmetic, sixteen-unit BMP spans,
packed generic scalar writes, or reordered surrogate classification/validation
provided no useful mixed-input gain and were removed. A complete BMP/surrogate
window sharing the same tables passed the UTF suite, but its three-round large
mixed reuse minimum was 1,270.630 ns/op versus 1,108.869 ns/op for the selected
candidate measured in that same diagnostic session. The extra vector work
outweighed its reduced branch count; that experiment was also removed.

## Remaining work

Large mixed UTF-16→UTF-8 remains the external gap in this corpus. Closing it
requires reducing work across BMP/surrogate transitions while protecting
short inputs and uniform-script paths. Broader APIs, less repetitive inputs,
and other hardware remain part of the active optimization objective.

## Reproduce

Use the [external build commands](utf16-conversion-2026-11-26.md#reproduce),
and rebuild both predecessors with the same benchmark source:

```sh
zig build bench-utf16-build
for revision in 854fca0 1af201c; do
  revision_dir="/tmp/icuz-packing-$revision"
  mkdir -p "$revision_dir"
  git archive "$revision" src/unicode/utf16.zig src/unicode/utf src/unicode/scalar | tar -x -C "$revision_dir"
  zig build-exe -O ReleaseFast -lc --dep utf16 -Mroot=bench/utf16/bench.zig \
    -O ReleaseFast -Mutf16="$revision_dir/src/unicode/utf16.zig" \
    -femit-bin="/tmp/icuz-packing-$revision-rebuilt"
done
python3 bench/utf16/compare.py --icuz zig-out/bin/icuz-utf16-bench \
  --baseline /tmp/icuz-packing-854fca0-rebuilt --baseline-reuse \
  --reference /tmp/icuz-packing-1af201c-rebuilt \
  --external /tmp/icuz-transcode-external --cpu 2 --rounds 5 --interleave-cases \
  --output /tmp/icuz-packing-reproduced.json
```
